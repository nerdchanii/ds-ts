# 동적 배열 (Dynamic Array)

## 1. 추상 자료형(ADT) 정의

순서가 있는 원소의 나열로, 인덱스로 임의 접근할 수 있고 크기가 자동으로 늘고 준다.
`T`는 원소 타입이며 인덱스는 0부터 시작한다.

| 연산 | 사전 조건 | 사후 조건 |
|---|---|---|
| `push(v)` | 없음 | size가 1 늘고, 마지막 원소가 `v` |
| `pop(): T` | `size > 0` (아니면 `RangeError`) | 마지막 원소를 반환하고 size가 1 줄어듦 |
| `get(i): T` | `0 <= i < size` | 상태 변화 없음, `i`번째 원소 반환 |
| `set(i, v)` | `0 <= i < size` | `i`번째 원소가 `v`로 교체, size 불변 |
| `insertAt(i, v)` | `0 <= i <= size` (`i == size`는 끝에 삽입) | `i` 이후 원소가 한 칸씩 밀리고 `v`가 `i`번째, size 1 증가 |
| `removeAt(i): T` | `0 <= i < size` | `i`번째 원소 반환, 뒤 원소가 한 칸씩 당겨지고 size 1 감소 |
| `size()` | 없음 | 원소 수 반환 |
| `capacity()` | 없음 | 현재 할당된 슬롯 수 반환 (항상 `>= size`) |
| `isEmpty()` | 없음 | `size == 0` 여부 |
| `clear()` | 없음 | `size == 0`, 용량은 최소 용량으로 복귀 |
| `toArray()` | 없음 | 원소를 순서대로 담은 내장 배열(복사본) |
| `[Symbol.iterator]()` | 없음 | 0번부터 순서대로 순회 (`for...of`, 스프레드 가능) |

범위를 벗어난 인덱스(음수, 정수가 아닌 값, NaN 포함)는 모두 `RangeError`다.

## 2. 왜 쓰는가

- **크기를 미리 모르는 데이터**를 모을 때: 입력 파싱 결과, 로그 버퍼, 검색 결과 목록.
- **인덱스 접근이 O(1)** 이면서 **끝에 붙이는 일이 잦은** 경우: 스택 구현, 정렬 전 데이터 적재, 해시 테이블의 버킷 배열.
- 연속된 메모리라 **캐시 효율**이 좋아 연결 리스트보다 순회가 대체로 빠르다.
- 실제 사례: JS `Array`, Java `ArrayList`, C++ `std::vector`, Python `list`, Go `slice`가 모두 이 구조다.

## 3. 구현 방식

- `slots = new Array(capacity)` 로 **고정 길이 슬롯**을 잡고, 실제 원소 수는 `length` 필드로 따로 센다.
  유효 원소는 `slots[0..length-1]` 에만 있다.
- **grow**: `push`/`insertAt` 시 `length == capacity` 이면 용량이 2배인 새 배열을 만들어 복사한 뒤 교체한다.
- **shrink**: `pop`/`removeAt` 후 `length <= capacity / 4` 이면 용량을 절반으로 줄인다. 단 최소 용량(4) 밑으로는 줄이지 않는다.
- 축소 기준을 1/2가 아니라 **1/4**로 잡은 이유: 1/2로 하면 경계에서 push/pop을 번갈아 할 때마다 확장과 축소가 반복(thrashing)되어 매번 O(n)이 든다.
  1/4 기준으로 줄이면 축소 직후 사용률이 1/2이므로, 다시 확장되거나 축소되려면 최소 `capacity/4`번의 연산이 필요하다.
- 제거된 슬롯은 `undefined`로 비워 참조를 놓아 준다(GC가 수거 가능).

## 4. 시간·공간 복잡도

| 연산 | 시간 | 비고 |
|---|---|---|
| `get` / `set` | O(1) | 인덱스로 직접 접근 |
| `push` | 평균 O(1), 최악 O(n) | 확장 시 복사 |
| `pop` | 평균 O(1), 최악 O(n) | 축소 시 복사 |
| `insertAt` | O(n) | 뒤 원소 이동 (끝 삽입은 평균 O(1)) |
| `removeAt` | O(n) | 뒤 원소 이동 (끝 제거는 평균 O(1)) |
| `size` / `capacity` / `isEmpty` | O(1) | |
| `clear` | O(1) | 새 최소 배열 할당 |
| `toArray` / 순회 | O(n) | |
| 공간 | O(n) | capacity는 size의 최대 4배 (최소 용량 제외) |

### amortized O(1) 분석: 왜 2배인가

`n`번 `push`했을 때 확장이 일어나는 시점의 복사 비용을 합한다. 초기 용량 1, 2배 확장이라고 하면
용량이 1, 2, 4, ... 로 찰 때마다 그 개수만큼 복사하므로 총 복사 횟수는

```
1 + 2 + 4 + ... + 2^k  = 2^(k+1) - 1  <  2n      (2^k < n 인 최대 k)
```

즉 n번 push의 총 비용은 `n`(쓰기) + `< 2n`(복사) = `< 3n` 이므로 **push 1회당 평균 3 이하, 곧 O(1)** 이다.
비싼 연산(복사)이 드물게 일어나고 그 비용이 앞선 값싼 push들에 나뉘어 상환(amortize)된다고 볼 수 있다.

**증가율 `r`배(r > 1)로 일반화**하면 복사 합은 등비급수

```
n/r + n/r^2 + ... = n / (r - 1)
```

이다.

| 배율 | n번 push 총 복사 횟수 | 최대 낭비 공간 |
|---|---|---|
| 2배 | n/(2-1) = **n** (앞의 2n 이내 상한과 같은 O(n)) | 용량의 최대 50% |
| 1.5배 | n/(1.5-1) = **2n** (역시 O(n)이지만 상수가 2배) | 용량의 최대 약 33% |

- **2배**: 복사 총량이 가장 적은 쪽(배율이 클수록 복사 합이 줄어든다). 대신 최악의 경우 빈 공간이 크다.
- **1.5배**: 메모리 낭비가 적고, 이전에 해제한 블록을 재사용하기 쉽다는 이점이 있어 일부 구현(예: Java `ArrayList`)이 택한다. 대신 복사 총량이 약 2배로 늘어난다.
- 반대로 **상수만큼만 증가(+k)** 하면 총 복사가 `n^2/k` 로 O(n^2)이 되어 amortized O(1)이 성립하지 않는다. 핵심은 "곱셈으로 늘린다"는 점이다.

축소도 같은 논리다. 1/4 이하에서 절반으로 줄이면 축소 직후 사용률이 1/2이므로, 다음 축소까지 최소 `capacity/4`번의 pop이 필요하고 이 횟수가 복사 비용 O(capacity)를 상환한다.

## 5. TypeScript로 구현할 때의 장단점·주의점

**장점**
- 제네릭 `DynamicArray<T>` 로 원소 타입이 컴파일 시점에 검사된다.
- `Symbol.iterator` 를 구현하면 `for...of`, 스프레드, `Array.from` 과 바로 호환된다.

**단점·주의점**
- JS 내장 배열은 이미 동적이라 이 구현은 **학습용**이다. 실제로는 성능·최적화 면에서 내장 `Array`가 낫다.
- `new Array(n)` 은 "구멍(hole)이 있는 희소 배열"이며 JS 엔진이 최적화를 달리 적용할 수 있다. 여기서는 길이를 고정해 두고 `length`로 유효 범위를 직접 관리한다.
- 빈 슬롯을 표현하려고 `undefined`를 쓰므로 슬롯 타입이 `T | undefined` 가 되고, 읽을 때 `as T` 단언이 필요하다.
  `T`가 `undefined`를 포함하는 경우에도 유효 범위는 `length` 로만 판단하므로 안전하다.
- 인덱스 검증이 필요하다. 내장 배열은 범위 밖 읽기에 `undefined`를 주지만 여기서는 `RangeError`를 던진다. `1.5`, `NaN` 같은 값도 막아야 한다.
- `pop`/`removeAt` 시 슬롯을 `undefined`로 비우지 않으면 제거된 객체가 GC되지 않는 **메모리 누수**가 생긴다.
- 숫자 인덱스 `number`는 정수 보장이 없으므로 `Number.isInteger` 검사가 필요하다.
