# 힙 (Heap) : BinaryHeap / PriorityQueue

## 1. 추상 자료형(ADT) 정의

**우선순위 큐(Priority Queue) ADT**: 원소들의 모음에서 "가장 우선순위가 높은 원소"를 빠르게 꺼내는 자료형. 힙은 이를 구현하는 대표적인 자료구조다.
이 구현에서는 비교 함수 `compare(a, b) < 0` 이면 `a`가 먼저 나온다(기본은 최소 힙).

| 연산 | 사전 조건 | 사후 조건 |
| --- | --- | --- |
| `push(x)` | 없음 | `x`가 추가되고 `size`가 1 증가. 힙 성질 유지 |
| `pop()` | 없음 (비어 있으면 `undefined` 반환) | 우선순위가 가장 높은 원소를 반환하고 제거. `size`가 1 감소 |
| `peek()` | 없음 (비어 있으면 `undefined`) | 상태 변화 없음. 루트 원소 반환 |
| `size` | 없음 | 현재 원소 수 반환 |
| `isEmpty()` | 없음 | `size === 0` 여부 |
| `clear()` | 없음 | 모든 원소 제거, `size === 0` |
| `toArray()` | 없음 | 내부 배열의 복사본 반환(**정렬된 순서가 아니라 힙 순서**) |
| `BinaryHeap.from(items, cmp)` | `items`는 순회 가능 | 모든 원소를 담은 힙 생성(원본 불변), O(n) |

**불변식(힙 성질)**: 모든 노드는 자신의 부모보다 우선순위가 같거나 낮다. 즉 루트가 항상 최우선 원소다. 형제 사이에는 순서 제약이 없다.

`PriorityQueue<T>`는 `BinaryHeap`을 감싼 얇은 래퍼로 `enqueue` / `dequeue` / `peek` / `size` / `isEmpty` / `clear`를 제공한다.

## 2. 왜 쓰는가

"최솟값(최댓값)을 반복해서 꺼내면서 중간에 새 값도 계속 들어오는" 상황에서, 매번 정렬(O(n log n))하거나 선형 탐색(O(n))하는 대신 O(log n)에 해결한다.

- **다익스트라 최단 경로**: 아직 확정되지 않은 정점 중 거리가 가장 짧은 것을 꺼낸다.
  ```ts
  const pq = new PriorityQueue<[number, string]>((a, b) => a[0] - b[0]);
  pq.enqueue([0, "start"]);
  while (!pq.isEmpty()) {
    const [dist, node] = pq.dequeue()!;
    // dist가 이미 알려진 최단거리보다 크면 건너뛰고, 아니면 이웃의 거리를 갱신해 enqueue
  }
  ```
- **Top-K**: 데이터 n개 중 가장 큰 K개를 찾을 때, 크기 K의 **최소 힙**을 유지한다. 새 값이 `peek()`보다 크면 `pop()` 후 `push()`. 시간 O(n log K), 공간 O(K)라서 전체 정렬보다 유리하고 스트림 데이터에도 쓸 수 있다.
- 그 밖에: 작업 스케줄러, 이벤트 시뮬레이션, 허프만 코딩, 중앙값 유지(힙 2개), 힙 정렬.

## 3. 구현 방식

### 배열로 표현한 완전 이진 트리
힙은 **완전 이진 트리**(마지막 레벨을 제외하고 꽉 차 있고, 마지막 레벨은 왼쪽부터 채움)이므로 포인터 없이 배열 하나로 표현된다.

```
인덱스:   0   1   2   3   4   5   6
값:      [1,  3,  2,  7,  4,  8,  5]

            1(0)
          /      \
       3(1)      2(2)
      /   \      /   \
    7(3) 4(4)  8(5) 5(6)
```

- 부모: `(i - 1) >> 1`
- 왼쪽 자식: `2i + 1`
- 오른쪽 자식: `2i + 2`

### sift-up (push)
맨 끝에 값을 넣고, 부모보다 우선순위가 높으면 부모를 아래로 내리며 올라간다. 최대 트리 높이(⌊log₂ n⌋)만큼 반복.

### sift-down (pop)
루트를 꺼내고 **마지막 원소를 루트로 옮긴 뒤**, 두 자식 중 우선순위가 높은 쪽과 비교해 자식이 더 높으면 자리를 바꾸며 내려간다. 구현은 매번 swap하지 않고 "빈 자리"에 자식을 끌어올린 뒤 마지막에 값을 한 번만 쓰는 방식이라 쓰기 횟수가 적다.

### heapify (`from`, Floyd 알고리즘)
빈 힙에 n번 push하면 O(n log n)이지만, 배열을 그대로 두고 **마지막 내부 노드 `(n-2)>>1`부터 루트까지 거꾸로 sift-down**하면 O(n)이다.

**O(n)인 이유**: 높이 h인 노드의 sift-down 비용은 최대 h다. 높이 h인 노드는 약 n / 2^(h+1)개이므로 총 비용은
Σ h · n / 2^(h+1) = n · Σ h / 2^(h+1) ≤ n · 1 = O(n) (급수 Σ h/2^h 는 2로 수렴).
핵심은 노드의 절반이 리프(비용 0)이고, 비용이 큰 윗 레벨의 노드 수는 급격히 적다는 점이다. 반면 push 반복은 노드 대부분(아래쪽)이 큰 비용(log n)을 쓴다.

### 안정성
힙은 **안정(stable)하지 않다**. 우선순위가 같은 원소들이 들어온 순서대로 나온다는 보장이 없다(sift 과정에서 자리가 바뀜). 순서가 필요하면 `[우선순위, 삽입번호]`를 비교 키로 쓰면 된다.

## 4. 연산별 시간·공간 복잡도

| 연산 | 시간 | 비고 |
| --- | --- | --- |
| `push` | O(log n) 최악, 평균 O(1) 근방 | sift-up (배열 끝 추가는 분할상환 O(1)) |
| `pop` | O(log n) | sift-down |
| `peek` | O(1) | |
| `size` / `isEmpty` | O(1) | |
| `clear` | O(1) | `length = 0` (GC 해제 비용은 별도) |
| `toArray` | O(n) | 복사 |
| `from` (heapify) | O(n) | Floyd |
| 임의 원소 검색/삭제 | O(n) | 이 구현은 제공하지 않음 |
| 힙 정렬 (from + n번 pop) | O(n log n) | |

공간: 원소 n개에 대해 O(n) (추가 포인터 없음). `from`은 입력 복사본을 만들므로 임시로 O(n)을 더 쓴다.

## 5. TypeScript로 구현할 때의 장단점·주의점

**장점**
- 제네릭 `BinaryHeap<T>`와 `Comparator<T>`로 숫자·튜플·객체 어떤 타입에도 같은 코드를 쓸 수 있다.
- JS 배열이 동적으로 늘어나므로 용량 관리가 필요 없다.
- 배열 기반이라 캐시 지역성이 좋고, 객체 노드 방식보다 메모리 오버헤드가 적다.

**단점·주의점**
- **기본 비교 함수 주의**: `Array.prototype.sort`의 기본 비교는 문자열 기준이지만, 여기 기본 비교는 `<`, `>` 연산이다. 숫자·문자열엔 맞지만 객체에는 의미가 없으니 반드시 comparator를 넘겨야 한다.
- 숫자 비교에 `a - b`를 쓸 때 `Infinity - Infinity`는 `NaN`이 되고, `NaN`이 섞이면 힙 성질이 깨진다. 값 범위에 유의한다.
- 비어 있을 때 `pop()`/`peek()`은 `undefined`를 반환하므로 반환 타입이 `T | undefined`다. `T` 자체가 `undefined`를 포함하면 "비었음"과 구분되지 않으니 `isEmpty()`로 먼저 확인한다.
- `from`에서 `push(...array)` 스프레드는 아주 큰 배열(수십만 이상)에서 호출 스택 한계에 걸릴 수 있다. 이 구현은 교육용이라 허용했지만 실무에서는 반복문으로 복사하는 편이 안전하다.
- 임의 원소의 우선순위 변경(decrease-key)은 지원하지 않는다. 다익스트라에서는 같은 정점을 중복 enqueue하고 꺼낼 때 낡은 항목을 건너뛰는 방식(lazy deletion)을 쓴다.
- `toArray()`는 정렬 결과가 아니라 힙 배열이다. 정렬 결과가 필요하면 `pop()`을 반복해야 한다.
- 표준 라이브러리에 내장 힙/우선순위 큐가 없어서 직접 만들어야 한다는 점이 JS/TS의 특징이다.
