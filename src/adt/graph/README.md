# 그래프 (Graph)

정점(vertex)과 그 사이를 잇는 간선(edge)으로 "관계"를 표현하는 자료구조.

## 1. 추상 자료형(ADT) 정의

`Graph<T>` = 정점 집합 V와 간선 집합 E. 옵션으로 방향/무방향을 정한다(`{ directed }`, 기본 무방향).

| 연산 | 사전 조건 | 사후 조건 |
|---|---|---|
| `addVertex(v)` | 없음 | `hasVertex(v) === true`. 이미 있으면 변화 없음 |
| `addEdge(u, v, w = 1)` | w가 NaN이 아님 | u, v가 없으면 생성됨. `hasEdge(u,v)` true (무방향이면 `hasEdge(v,u)`도). 기존 간선이면 가중치 덮어씀 |
| `removeEdge(u, v)` | 없음 | 간선이 없어짐(무방향이면 양쪽). 지웠으면 true, 없었으면 false |
| `removeVertex(v)` | 없음 | v와 v에 닿는 모든 간선 제거. 지웠으면 true |
| `hasVertex(v)`, `hasEdge(u, v)` | 없음 | 상태를 바꾸지 않음. 정점이 없어도 false 반환 |
| `neighbors(v)` | v가 존재 | v에서 나가는 간선의 도착 정점 배열 |
| `vertices()`, `edges()` | 없음 | 무방향의 `edges()`는 각 간선을 한 번만 반환 |
| `degree(v)` / `outDegree(v)` / `inDegree(v)` | v가 존재 | 이웃 수 / 나가는 간선 수 / 들어오는 간선 수 |
| `bfs(start)`, `dfs(start)` | start가 존재 | start에서 도달 가능한 정점을 방문 순서대로 반환 |
| `shortestPathUnweighted(s, e)` | s, e 존재 | 간선 수가 최소인 경로 배열(s, e 포함). 도달 불가면 `undefined` |
| `dijkstra(start)` | start 존재, 모든 가중치 >= 0 | 모든 정점 -> 최단 거리 `Map`. 도달 불가는 `Infinity`. 음수 가중치면 `RangeError` |
| `topologicalSort()` | 방향 그래프 | 모든 간선 (u,v)에서 u가 v보다 앞인 순서. **사이클이면 `undefined`** (무방향이면 Error) |
| `connectedComponents()` | 무방향 그래프 | 연결 요소별 정점 배열 (방향이면 Error) |

"사전 조건 위반"은 `Error`를 던진다. 단 `has*`/`remove*`는 대상이 없으면 `false`로 조용히 응답한다.

## 2. 왜 쓰는가

세상의 많은 문제가 "무언가와 무언가의 관계"이고, 그것이 곧 그래프다.

- 지도/내비게이션: 교차로 = 정점, 도로 = 가중치 간선 -> 최단 경로(다익스트라)
- 소셜 네트워크: 사람 = 정점, 친구 관계 = 간선 -> "친구의 친구" 탐색(BFS), 커뮤니티(연결 요소)
- 빌드/패키지 의존성, 수강 선수 과목: 방향 그래프 -> 위상 정렬로 실행 순서 결정, 사이클이면 순환 의존 오류
- 네트워크 라우팅, 웹 크롤링, 게임 맵 길 찾기, 미로 탐색

## 3. 구현 방식

`Map<T, Map<T, number>>` 형태의 **인접 리스트**. 바깥 Map은 `정점 -> 이웃 표`, 안쪽 Map은 `이웃 -> 가중치`.
이웃 목록을 배열 대신 Map으로 둔 덕분에 `hasEdge`, 간선 삭제, 가중치 조회가 평균 O(1)이다.

- **무방향**: `addEdge(u,v)`가 `u->v`, `v->u` 두 칸을 모두 기록한다. 방향 그래프는 `u->v` 한 칸만.
- **BFS (큐)**: 가까운 정점부터 레벨 순으로 방문. 배열 + head 인덱스로 큐를 만든다(`shift()`는 O(n)이라 피함). 큐에 넣을 때 방문 표시한다.
- **DFS (스택)**: 한 갈래를 끝까지 파고든 뒤 되돌아온다. 재귀 대신 명시적 스택을 쓰며, 이웃을 역순으로 push해 재귀 DFS와 같은 순서를 만든다. 스택에 중복이 들어올 수 있어 pop할 때 방문 여부를 검사한다.
- **다익스트라**: 파일 내부의 비공개 최소 힙 사용. 거리 갱신 시 새 항목을 push하고 낡은 항목은 pop 때 버린다(지연 삭제).
- **위상 정렬**: Kahn 알고리즘. 진입 차수 0인 정점을 큐에서 꺼내며 간선을 "제거"한다. 결과 길이가 정점 수보다 작으면 사이클이므로 `undefined`를 반환한다.
- **연결 요소**: 아직 방문하지 않은 정점마다 BFS를 돌린다.

### BFS와 DFS의 큐/스택 대응

두 알고리즘은 코드가 거의 같고 **"다음에 방문할 정점을 꺼내는 자료구조"만 다르다.**

| | BFS | DFS |
|---|---|---|
| 자료구조 | 큐 (FIFO) | 스택 (LIFO) |
| 탐색 모양 | 시작점에서 가까운 순(레벨별) | 한 방향으로 깊게, 막히면 되돌아감 |
| 최단 경로(비가중) | 보장 | 보장 안 됨 |
| 대표 용도 | 최단 거리, 최소 이동 횟수 | 사이클 탐지, 경로 존재, 백트래킹 |
| 재귀 | 필요 없음 | 재귀 = 호출 스택이 곧 스택. 깊으면 오버플로 위험 |

### 인접 행렬 vs 인접 리스트

| 항목 | 인접 행렬 (V x V 배열) | 인접 리스트 (이 구현) |
|---|---|---|
| 공간 | O(V^2) | O(V + E) |
| `hasEdge(u,v)` | O(1) | 평균 O(1) (Map), 배열 리스트면 O(deg) |
| 이웃 순회 | O(V) | O(deg(v)) |
| 전체 간선 순회 | O(V^2) | O(V + E) |
| 간선 추가/삭제 | O(1) | 평균 O(1) |
| 정점 추가/삭제 | 행렬 재할당 O(V^2) | 추가 O(1), 삭제 O(V) |
| 유리한 경우 | 밀집 그래프(E ~ V^2), 간선 존재 질의가 잦을 때 | 희소 그래프(대부분의 실제 그래프) |

### 방향 / 무방향, 가중치

- **무방향**: 간선에 방향이 없다(친구 관계, 양방향 도로). **방향**: 간선이 `from -> to`로 한쪽(팔로우, 의존성, 일방통행). 방향 그래프에서는 degree가 in/out으로 나뉜다.
- **가중치**: 간선에 비용(거리, 시간, 요금)을 붙인다. 기본값 1이면 사실상 비가중이다. BFS 최단 경로는 가중치를 무시하고 간선 수만 센다. 가중 최단 경로는 다익스트라이며 음수 가중치에서는 틀리므로 거부한다(음수에는 벨만-포드가 필요).
- 무방향 그래프에서 자기 루프(u-u)의 `degree`는 이웃 수 기준이라 1로 센다(수학적 정의의 2와 다름).

## 4. 시간·공간 복잡도

V = 정점 수, E = 간선 수, deg(v) = v의 이웃 수.

| 연산 | 시간 | 비고 |
|---|---|---|
| `addVertex` | O(1) | 평균 |
| `addEdge` | O(1) | 평균 |
| `removeEdge` | O(1) | 평균 |
| `removeVertex` | O(V) | 모든 행에서 해당 정점을 지움 |
| `hasVertex` / `hasEdge` | O(1) | 평균 |
| `neighbors` / `degree` / `outDegree` | O(deg(v)) / O(1) / O(1) | `neighbors`는 배열 복사 |
| `inDegree` | O(V) | 역방향 인덱스가 없음 |
| `vertices` / `edges` | O(V) / O(V + E) | |
| `bfs` / `dfs` | O(V + E) | 보조 공간 O(V) |
| `shortestPathUnweighted` | O(V + E) | 보조 공간 O(V) |
| `dijkstra` | O((V + E) log V) | 지연 삭제 힙에는 최대 E개 항목. 공간 O(V + E) |
| `topologicalSort` | O(V + E) | 공간 O(V) |
| `connectedComponents` | O(V + E) | 공간 O(V) |
| 그래프 자체 | 공간 O(V + E) | 무방향은 간선당 두 칸 저장 |

## 5. TypeScript로 구현할 때의 장단점·주의점

- **제네릭 정점 `T`**: 문자열, 숫자 등 원시값은 `Map` 키로 잘 동작한다. 하지만 **객체 정점은 참조 동일성(===)** 으로 비교되므로 `{id:1}`을 두 번 만들면 서로 다른 정점이다. 객체를 쓰려면 같은 인스턴스를 재사용하거나 `id` 같은 원시 키를 정점으로 쓰자.
- **`Map`의 삽입 순서 보장**: 이웃/정점 순회 순서가 결정적이라 테스트와 디버깅이 쉽다. 단, 이 순서에 의존하는 결과(BFS/DFS 순서, 위상 정렬 결과)는 "여러 정답 중 하나"임을 기억하자. 위상 정렬 검증은 순서 자체가 아니라 "모든 간선에서 앞/뒤 관계"로 해야 한다.
- **재귀 금지**: JS 엔진의 호출 스택은 보통 수천~만 단위에서 넘친다. 정점이 많은 체인 그래프에서 재귀 DFS는 `RangeError`가 나므로 명시적 스택을 썼다.
- **큐는 `shift()` 금지**: 배열 `shift()`는 O(n)이라 BFS가 O(V^2)로 느려질 수 있다. head 인덱스 방식은 메모리를 다 쓸 때까지 앞부분을 안 비우지만 한 번 쓰고 버리는 큐에는 충분하다.
- **표준 라이브러리에 힙이 없다**: 다익스트라를 위해 직접 이진 힙을 구현해야 한다(여기선 파일 내부 비공개 클래스).
- **부동소수점**: 가중치가 소수면 거리 합에 오차가 생길 수 있어 테스트에서 `toBeCloseTo`를 쓰거나 정수 단위로 바꿔 다루는 편이 안전하다. `Infinity`는 "도달 불가"의 표식으로 쓰였다.
- **타입 안전성 한계**: `strict` 모드에서도 `Map.get()`은 `undefined`를 포함하므로 불변식상 존재가 확실한 곳엔 `!`를 쓰게 된다. 불변식이 깨지지 않도록 `adj` 필드는 `private`으로 감췄다.
