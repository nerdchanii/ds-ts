# 트라이 (Trie)

문자열 집합을 **글자 단위 경로**로 저장하는 트리. 접두사(prefix) 질의에 특화된 자료구조다.

## 1. 추상 자료형(ADT) 정의

**도메인**: 문자열(유니코드 코드포인트의 열)의 집합 S. 중복은 허용하지 않는다. (선택: 각 단어에 값 V 하나를 붙일 수 있다.)

| 연산 | 사전 조건 | 사후 조건 / 반환 |
| --- | --- | --- |
| `insert(w, v?)` | 없음 (빈 문자열도 가능) | w ∈ S. 새 단어면 size 가 1 증가하고 `true`, 이미 있으면 값만 갱신하고 `false` |
| `has(w)` | 없음 | w ∈ S 이면 `true`. 상태 불변. (`"app"`만 있을 때 `has("ap")`는 `false`) |
| `startsWith(p)` | 없음 | S 에 p 로 시작하는 단어(p 자신 포함)가 있으면 `true`. 상태 불변 |
| `remove(w)` | 없음 | w ∈ S 였다면 제거 후 `true`, size 1 감소. 아니면 `false`이고 상태 불변. 다른 단어(`app` 삭제 시 `apple`)는 영향 없음 |
| `autocomplete(p, limit?)` | 없음 | p 로 시작하는 단어를 **사전순**으로 최대 limit 개 반환. `limit <= 0` 이면 빈 배열. 상태 불변 |
| `countWithPrefix(p)` | 없음 | p 로 시작하는 단어 수. `countWithPrefix("") == size` |
| `size` / `isEmpty()` | 없음 | 단어 수 / `size == 0` 여부 |
| `clear()` | 없음 | S = ∅ |
| `[Symbol.iterator]` | 순회 중 수정하지 않는다 | S 의 모든 단어를 사전순으로 한 번씩 방문 |

**불변식**
- `size == |S|`
- 모든 노드의 `wordCount` = 그 부분 트리에 속한 단어 수
- 단어의 끝이 아니면서 자식도 없는 노드(루트 제외)는 존재하지 않는다 (삭제 시 가지치기)

## 2. 왜 쓰는가

**해시셋과의 차이.** 해시셋도 `has` 는 평균 O(1) 이지만, 해시는 문자열을 뭉개 버리기 때문에 "`app` 으로 시작하는 단어가 뭐지?" 같은 **접두사 질의**를 풀 수 없다. 해시셋으로는 전체를 훑어야(O(N·L)) 한다. 트라이는 접두사 길이만큼만 내려가면 그 아래 부분 트리 전체가 곧 답이다. 또한 순회하면 자연스럽게 사전순이 나오므로 별도의 정렬이 필요 없다.

| 요구 | 해시셋 | 트라이 |
| --- | --- | --- |
| 정확히 있는지 | O(L) 평균 | O(L) 최악 |
| 접두사로 시작하는 단어 존재 여부 | O(N·L) | O(P) |
| 접두사로 시작하는 단어 개수 | O(N·L) | O(P) (이 구현) |
| 사전순 나열 | 정렬 필요 O(N log N · L) | 순회만으로 가능 |

(N: 단어 수, L: 단어 길이, P: 접두사 길이)

**실제 사용 예**
- **자동완성**: 검색창에 `사` 를 치면 `사과`, `사과나무`, `사랑`, `사자` 를 제안 (`autocomplete("사", 4)`).
- **사전/맞춤법 검사, 단어 게임**: 단어 존재 확인과 "이 글자열로 시작하는 단어가 아직 있나?" 가지치기 (보글보글, 십자말풀이 탐색).
- **IP 라우팅의 최장 접두사 매칭**, 전화번호부 검색, 금칙어 필터(Aho-Corasick 의 기반).

## 3. 구현 방식

```
         (root)
          /    \
         a      b
         |      |
         p      a ...
         |
         p*          <- "app" 끝 (*)
         |
         l
         |
         e*          <- "apple" 끝
```

- **노드**: `children: Map<string, TrieNode>`, `isEnd`(단어 끝 표시), `value`(선택 값), `wordCount`(부분 트리의 단어 수).
- **글자 단위**: `for (const ch of word)` 로 코드포인트 단위 순회. `"🍎"` 처럼 UTF-16 으로 2칸을 차지하는 문자도 한 글자로 취급하고, 한글 음절(`사`)도 한 글자다.
- **insert**: 먼저 `has` 로 새 단어인지 확인한 뒤, 경로를 따라가며 없는 노드는 만들고 경로상 `wordCount` 를 1씩 올린다. 마지막 노드에 `isEnd = true`.
- **remove**: 경로를 (부모, 글자, 노드) 배열에 기록하며 내려가 `wordCount` 를 줄이고 `isEnd` 를 끈다. 그다음 **리프에서 루트 방향으로** 올라가며 `isEnd` 가 아니고 자식도 없는 노드를 부모에서 지운다. 다른 단어가 쓰는 노드(예: `app` 삭제 시 `apple` 이 지나는 노드)를 만나면 즉시 멈춘다. 전부 반복문이라 재귀 깊이 문제가 없다.
- **autocomplete / iterator**: 접두사 노드를 찾은 뒤 **명시적 스택 DFS(전위 순회)**. 자식 키를 코드포인트 순으로 정렬해 역순으로 스택에 넣으면 사전순으로 나오고, 전위 순회라 `app` 이 `apple` 보다 앞선다. 제너레이터라서 `limit` 개를 얻으면 바로 멈춘다.
- **countWithPrefix**: 노드에 단어 수를 유지하므로 접두사 노드를 찾기만 하면 O(P).

## 4. 시간·공간 복잡도

N: 저장된 단어 수, L: 단어 길이, P: 접두사 길이, K: 접두사 아래 부분 트리의 노드 수, M: 반환 단어 수, σ: 한 노드의 자식 수.

| 연산 | 시간 | 비고 |
| --- | --- | --- |
| `insert` | O(L) | `has` 확인 + 삽입, Map 연산을 평균 O(1) 로 본 값 |
| `has` | O(L) | N 과 무관 |
| `startsWith` | O(P) | |
| `remove` | O(L) | 경로 기록 + 가지치기 |
| `countWithPrefix` | O(P) | `wordCount` 덕분 |
| `autocomplete(p, limit)` | O(P + K·σ log σ) 최악 | 노드마다 자식 키를 정렬. limit 로 조기 종료 가능 |
| 전체 순회 (iterator) | O(전체 노드 수 · σ log σ) | |
| `size`, `isEmpty` | O(1) | |
| `clear` | O(1) (참조 해제, 이후 GC) | |

**공간**: 최악 O(전체 글자 수) 노드. 공통 접두사가 많을수록 절약된다. 노드마다 Map 객체와 필드 오버헤드가 있어 노드 하나가 수십~백 바이트 수준이다. 임시 공간은 `remove` 에서 O(L), `autocomplete` 에서 스택 + 결과 문자열.

## 5. TypeScript 구현 시 장단점과 주의점

**장점**
- `Map<string, TrieNode>` 라서 알파벳이 고정이 아니다. 배열(`children[26]`) 방식과 달리 한글·이모지·임의 문자를 그대로 쓸 수 있고, 안 쓰는 글자의 칸을 낭비하지 않는다.
- 제너레이터와 `Symbol.iterator` 로 지연 순회를 간결하게 표현할 수 있다. 제네릭 `V` 로 사전(단어 -> 뜻) 용도로도 쓴다.

**단점 / 공간 문제**
- 트라이의 가장 큰 약점은 **공간**이다. 글자마다 노드 하나 + Map 하나를 만들므로 단어 수가 많으면 해시셋보다 메모리를 훨씬 먹고, 포인터를 따라가야 해 캐시 효율도 나쁘다. (JS 객체/Map 의 오버헤드는 특히 크다.)
- 해결책 중 하나는 **압축 트라이(radix tree / Patricia trie)**: 자식이 하나뿐인 연속된 노드를 간선 하나에 문자열로 합쳐 노드 수를 단어 수 수준으로 줄인다. 그 외 DAWG(접미사까지 공유), 이중 배열 트라이도 있다. 이 구현은 학습을 위해 일반 트라이를 택했다.

**주의점**
- **코드 유닛이 아닌 코드포인트로 순회**: `word[i]` 나 `split("")` 은 이모지를 반쪽씩 쪼갠다. 반드시 `for...of` 를 쓴다. 그래도 `é` 를 `e` + 결합 악센트로 쓴 경우나 자모 분리형(NFD) 한글은 여러 코드포인트이므로, 삽입/조회 전에 `normalize("NFC")` 를 맞추는 것이 안전하다.
- **사전순의 기준**: 이 구현은 코드포인트 순이다. UTF-16 코드 유닛 순(`Array.prototype.sort` 기본)과 BMP 밖 문자에서 다를 수 있고, 로캘별 정렬(`localeCompare`)과도 다르다.
- **대소문자/공백**: 같은 단어로 취급하려면 호출하는 쪽에서 `toLowerCase()`, `trim()` 으로 정규화한다.
- **긴 단어와 재귀**: 삭제와 순회를 반복문/명시적 스택으로 구현해 10만 글자 단어에서도 호출 스택이 넘치지 않는다. 재귀로 쓰면 단어 길이만큼 스택이 깊어진다.
- 순회 중에 `insert`/`remove` 를 하면 결과가 정의되지 않는다.
