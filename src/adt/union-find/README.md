# 서로소 집합 (Union-Find / Disjoint Set Union)

원소들을 겹치지 않는 그룹(집합)으로 나눠 관리하고, "두 원소가 같은 그룹인가?"와 "두 그룹을 합친다"를 거의 O(1)에 처리하는 자료구조.

## 1. 추상 자료형(ADT) 정의

원소의 전체 집합 U 위에서, 서로 겹치지 않고 합집합이 U인 부분집합들의 모임(분할)을 유지한다. 각 집합은 **대표 원소** 하나를 가지며, 같은 집합의 원소는 항상 같은 대표를 갖는다.

| 연산 | 사전 조건 | 사후 조건 |
| --- | --- | --- |
| `makeSet(x)` | x가 아직 U에 없음 | `{x}` 가 새 집합이 되고 집합 수 +1 |
| `find(x)` | x ∈ U | x가 속한 집합의 대표를 반환. 집합이 바뀌지 않는 한 같은 집합의 모든 원소에 대해 같은 값 |
| `union(a, b)` | a, b ∈ U | a, b가 속한 두 집합이 하나로 합쳐짐. 서로 다른 집합이었다면 집합 수 -1, `true` 반환. 이미 같으면 아무 변화 없이 `false` |
| `connected(a, b)` | a, b ∈ U | `find(a) === find(b)` 를 반환. 상태 불변 |
| `componentCount()` | 없음 | 현재 집합의 개수 |
| `sizeOf(x)` | x ∈ U | x가 속한 집합의 원소 수 |

불변식: 집합들은 항상 서로소이며, 합쳐진 집합은 다시 나뉘지 않는다(분리 연산 없음).
사전 조건을 어기면(범위 밖 원소, 미등록 키) `RangeError`.

이 레포의 구현은 두 가지다.
- `UnionFind`: 원소가 `0..n-1` 정수. `add()`로 원소를 하나씩 늘릴 수도 있다.
- `KeyedUnionFind<T>`: 임의의 키. `makeSet`으로 등록한 뒤 `find/union/connected/sizeOf`를 쓴다.

## 2. 왜 쓰는가

"그룹 합치기 + 같은 그룹인지 묻기"가 반복되는 문제에서, 매번 그래프 탐색(BFS/DFS)을 하면 질의마다 O(V+E)가 든다. Union-Find는 간선이 **추가만** 되는(온라인) 연결성 문제를 거의 상수 시간에 푼다.

- **크루스칼 최소 신장 트리**: 간선을 가중치순으로 보며 두 끝점이 이미 연결되어 있으면(사이클) 건너뛴다.
- **네트워크 연결성**: 컴퓨터/도로가 하나씩 연결될 때 "A와 B가 통하는가", "고립 덩어리가 몇 개인가"를 즉시 답한다.
- 그래프 사이클 검출, 동치 관계 묶기(계정 병합, 동의어 그룹), 격자 연결 요소(이미지 영역, 퍼콜레이션).

### 예시: 크루스칼 MST

```ts
const uf = new UnionFind(V);
let total = 0;
for (const [u, v, w] of edges.sort((a, b) => a[2] - b[2])) {
  if (uf.union(u, v)) total += w; // 합쳐졌다 = 사이클이 아니다 = MST 간선
}
```

### 예시: 네트워크 연결성

```ts
const net = new KeyedUnionFind<string>();
["서울", "부산", "대전", "제주"].forEach((c) => net.makeSet(c));
net.union("서울", "대전");
net.union("대전", "부산");
net.connected("서울", "부산"); // true
net.componentCount();          // 2 (제주는 고립)
```

## 3. 구현 방식

### 트리로 표현하기

각 집합을 트리 하나로 보고, 노드는 **부모 포인터만** 가진다. 배열 `parent[i]`에 부모를 저장하고, 루트는 `parent[r] === r` 로 표시한다. 루트가 곧 대표 원소다.

```
parent = [0, 0, 1, 3, 3]      집합 {0,1,2}: 0 <- 1 <- 2
                              집합 {3,4}  : 3 <- 4
```

- `find(x)`: 부모를 따라 루트까지 올라간다.
- `union(a, b)`: 한쪽 루트를 다른 쪽 루트의 자식으로 붙인다.
- `connected(a, b)`: 두 루트가 같은지 비교한다.

### 최적화 1: 경로 압축 (path compression)

`find(x)` 때 지나온 모든 노드를 루트에 직접 연결해 다음 탐색을 짧게 만든다. 구현은 재귀 없이 **반복형 2-pass**다. (1) 루트까지 올라가 루트를 찾고, (2) 다시 x에서 출발해 경로의 모든 노드의 `parent`를 루트로 바꾼다. 재귀를 쓰지 않으므로 깊은 트리에서도 스택 오버플로가 없다.

### 최적화 2: 크기 기준 합치기 (union by size)

두 루트를 합칠 때 **원소 수가 작은 트리를 큰 트리 밑에** 붙인다. 이렇게 하면 어떤 노드의 깊이가 1 늘어날 때마다 그 노드가 속한 집합의 크기가 최소 2배가 되므로 트리 높이가 O(log n)로 제한된다. 루트의 `sizes`를 유지하므로 `sizeOf`도 O(α(n))에 된다. (union by rank도 같은 효과이며, 크기를 쓰면 `sizeOf`를 공짜로 얻는다.)

### KeyedUnionFind

내부에 `Map<T, number>`(키→인덱스)와 `T[]`(인덱스→키)를 두고, 실제 합치기는 `UnionFind`에 위임하는 래퍼다. `makeSet`은 `UnionFind.add()`로 새 인덱스를 받아온다. 키 동등성은 Map 규칙이므로 객체 키는 참조로 구분된다.

## 4. 시간·공간 복잡도

n = 원소 수, m = 연산 횟수, α = 역아커만 함수.

| 연산 | 최적화 없음 (최악) | union by size만 | 경로 압축 + union by size |
| --- | --- | --- | --- |
| `find` | O(n) | O(log n) | 분할 상환 O(α(n)) |
| `union` | O(n) (find 포함) | O(log n) | 분할 상환 O(α(n)) |
| `connected` | O(n) | O(log n) | 분할 상환 O(α(n)) |
| `sizeOf` | - | O(log n) | 분할 상환 O(α(n)) |
| `componentCount` | O(1) | O(1) | O(1) |
| 생성 / `makeSet`, `add` | O(n) / O(1) | O(n) / O(1) | O(n) / O(1) (분할 상환) |
| 공간 | O(n) | O(n) | O(n) |

`KeyedUnionFind`는 위 연산에 Map 조회 O(1)(평균)이 더해질 뿐이며, 공간은 O(n)이다.

### 분석 요약

- **최적화가 없을 때 최악 O(n)**: `union(0,1), union(1,2), ...` 처럼 항상 새 원소의 루트를 기존 트리 밑에 붙이면 길이 n의 사슬이 만들어지고, 가장 깊은 노드의 `find`가 O(n)이다. n번 연산하면 총 O(n²).
- **union by size만 쓰면** 높이가 O(log n)이라 연산당 O(log n).
- **경로 압축까지 더하면** (Tarjan, 1975) m번의 연산에 총 O(m · α(n))이 든다. α(n)은 역아커만 함수로 극단적으로 느리게 증가해서, 우주의 원자 수 정도의 n에서도 5를 넘지 않는다. 즉 실무에서는 **사실상 상수**다. (유도 과정은 생략하고 결과만 적는다. 이 α(n) 하한은 이 자료구조 계열에서 더 줄일 수 없음이 증명되어 있다.)
- 경로 압축만 쓰고 합치기 최적화가 없으면 분할 상환 O(log n)이다. 둘을 같이 써야 α(n)이 된다.

## 5. TypeScript로 구현할 때의 장단점·주의점

- 배열 두 개(`parent`, `sizes`)만으로 충분해 객체/포인터 오버헤드가 없고, 캐시 친화적이다. 성능이 더 필요하면 `Int32Array`로 바꿀 수 있다(대신 `push`로 늘리는 `add()`는 재할당이 필요).
- **재귀 금지**: 경로 압축을 재귀로 쓰면 사슬이 깊을 때 JS의 호출 스택 한계(수만 단계)에 걸린다. 반복형 2-pass로 해결했고, 10만 개 사슬 테스트가 이를 확인한다.
- 정수 검증: JS의 `number`는 `1.5`, `NaN`, `-0` 등도 받아들이므로 `Number.isInteger`와 범위 검사로 `RangeError`를 던진다. 배열 범위 밖 접근은 `undefined`를 조용히 반환해 버그를 숨기기 쉽기 때문이다.
- 제네릭 `KeyedUnionFind<T>`는 Map 기반이라 키 동등성이 `SameValueZero`다. 값이 같은 서로 다른 객체(`{id:1}` 두 개)는 다른 키로 취급되므로, 필요하면 `id` 같은 원시값을 키로 쓴다. `NaN`은 자기 자신과 같은 키로 취급된다.
- `find`가 **읽기 연산처럼 보이지만 내부 상태를 바꾼다**(경로 압축). 외부에서 관찰되는 결과는 같지만 불변 객체로 가정하거나 동시에 접근하면 안 된다. JS는 단일 스레드지만 Worker 간 공유 시 주의.
- 분리(split)·원소 삭제는 지원하지 않는다. 필요하면 오프라인 처리나 다른 구조(link-cut tree 등)를 고려한다.
- 대표 원소는 합치기 규칙에 따라 정해지므로 "어떤 값이 대표인지"에 의존하는 코드는 피하고, 비교(`find(a) === find(b)`)에만 사용한다.
