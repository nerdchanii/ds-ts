# 이진 탐색 트리 (Binary Search Tree, BST)

## 1. 추상 자료형(ADT) 정의

이진 탐색 트리는 **순서가 있는 값의 집합(ordered set)** 을 표현하는 ADT 다. 이 구현은 중복 값을 허용하지 않는다(set 의미).

### 불변식 (정렬 순서 불변식)

모든 노드 `x` 에 대해 다음이 항상 성립한다.

```
(x 의 왼쪽 서브트리의 모든 값) < x.value < (x 의 오른쪽 서브트리의 모든 값)
```

이 불변식 덕분에 **중위 순회(inOrder)는 항상 오름차순**이 된다. 모든 연산은 이 불변식을 깨뜨리지 않아야 하고, 실제로 사전 조건이자 사후 조건이다.

### 연산

| 연산 | 사전 조건 | 사후 조건 |
| --- | --- | --- |
| `insert(v)` | 불변식 성립 | 새 값이면 `v` 가 포함되고 `size` +1, `true` 반환. 이미 있으면 변화 없이 `false`. 불변식 유지 |
| `has(v)` | 없음 | 트리 상태 변화 없음. `v` 가 있으면 `true` |
| `remove(v)` | 없음 | 있었다면 `v` 가 사라지고 `size` -1, `true`. 없었으면 변화 없이 `false`. 불변식 유지 |
| `min()` / `max()` | 없음 | 가장 작은/큰 값. 빈 트리면 `undefined`. 상태 변화 없음 |
| `successor(v)` | 없음 (`v` 가 트리에 없어도 됨) | `v` 보다 큰 값 중 최솟값, 없으면 `undefined` |
| `predecessor(v)` | 없음 | `v` 보다 작은 값 중 최댓값, 없으면 `undefined` |
| `height()` | 없음 | 루트에서 가장 깊은 노드까지의 노드 수. 빈 트리 0, 노드 1개 1 |
| `size` / `isEmpty()` | 없음 | 저장된 값의 개수 / `size === 0` |
| `clear()` | 없음 | `size === 0`, `isEmpty() === true` |
| `inOrder()` | 없음 | 오름차순으로 모든 값을 정확히 한 번씩 내놓음 |
| `preOrder()` / `postOrder()` | 없음 | 부모-왼쪽-오른쪽 / 왼쪽-오른쪽-부모 순서 |
| `levelOrder()` | 없음 | 깊이가 얕은 레벨부터, 같은 레벨은 왼쪽부터 |

값의 순서는 생성자에 주입하는 `comparator(a, b)` (a<b 음수, 같으면 0, a>b 양수)로 정한다. 생략하면 `<`, `>` 로 비교한다. 두 값을 비교해 0 이면 같은 키로 취급한다.

## 2. 왜 쓰는가

배열은 "정렬된 상태에서 탐색"은 빠르지만(이진 탐색 O(log n)) 삽입/삭제가 O(n) 이고, 연결 리스트는 삽입/삭제는 쉽지만 탐색이 O(n) 이다. BST 는 **정렬을 유지하면서 탐색·삽입·삭제를 모두 평균 O(log n)** 에 하려는 자료구조다.

실제 사용 예
- 정렬된 집합/맵: C++ `std::set`/`std::map`, Java `TreeMap`/`TreeSet` (내부는 Red-Black 트리)
- 범위 질의: "점수가 80~90 인 사용자", 가장 가까운 값(`successor`/`predecessor`) 찾기
- 데이터베이스 인덱스 (디스크용으로 변형된 B-트리 계열)
- 순서 통계, 스케줄러의 "가장 이른 마감 작업" 관리 등

## 3. 구현 방식

노드는 `value`, `left`, `right` 만 가진다. 루트와 개수(`count`)를 트리가 관리한다.

- **삽입/탐색**: 루트에서 시작해 `compare` 결과가 음수면 왼쪽, 양수면 오른쪽으로 내려가는 `while`/`for` 반복문. 0 이면 중복.
- **min/max**: 끝까지 왼쪽(오른쪽)으로 내려간다.
- **successor/predecessor**: 루트부터 내려가며 "후보"를 갱신한다. 부모 포인터가 필요 없고 값이 트리에 없어도 동작한다.
- **순회**: 재귀 대신 명시적 스택/큐 사용. 제너레이터(`function*`)이므로 필요한 만큼만 꺼내 쓸 수 있고, `for...of` 와 전개 연산자(`[...tree]`)가 된다.
- **삭제**: 삭제할 노드와 그 부모를 찾은 뒤 자식 수에 따라 세 가지로 나뉜다.

### 삭제의 세 가지 경우

**경우 1: 자식 0개 (리프)** - 부모의 링크를 `null` 로 바꾼다.

```
    8                8
   / \              / \
  3   10   -->     3   10        13 삭제 (리프)
       \                \
        13               (없음)
```

**경우 2: 자식 1개** - 노드를 건너뛰고 부모가 그 자식을 직접 가리키게 한다.

```
    8                8
   / \              / \
  3   10   -->     3   13        10 삭제 (자식 13 하나)
       \
        13
```

**경우 3: 자식 2개** - 오른쪽 서브트리의 최솟값(후속자)의 값을 복사해 온 뒤, 후속자 노드를 삭제한다. 후속자는 왼쪽 자식이 없으므로 경우 1 또는 2 로 끝난다. (왼쪽 서브트리의 최댓값인 선행자를 써도 된다.)

```
      3                   4
     / \                 / \
    1   6       -->     1   6          3 삭제
       / \                  \
      4   7                  7
   (후속자 = 오른쪽 서브트리의 최솟값 4 를 3 자리에 복사, 원래 4 노드 제거)
```

이렇게 해도 정렬 불변식이 유지되는 이유: 후속자는 삭제 노드보다 큰 값 중 가장 작으므로, 왼쪽 서브트리의 모든 값보다 크고 나머지 오른쪽 값보다 작다.

## 4. 연산별 시간·공간 복잡도

`n` = 노드 수, `h` = 트리 높이. 무작위 입력이면 평균 `h ≈ O(log n)`, 최악(정렬된 입력)이면 `h = n`.

| 연산 | 평균 (h = log n) | 최악 (h = n) | 추가 공간 |
| --- | --- | --- | --- |
| insert | O(log n) | O(n) | O(1) |
| has | O(log n) | O(n) | O(1) |
| remove | O(log n) | O(n) | O(1) |
| min / max | O(log n) | O(n) | O(1) |
| successor / predecessor | O(log n) | O(n) | O(1) |
| height | O(n) | O(n) | O(w) (w = 최대 레벨 너비) |
| size / isEmpty / clear | O(1) | O(1) | O(1) |
| inOrder / preOrder / postOrder 전체 | O(n) | O(n) | O(h) 스택 |
| levelOrder 전체 | O(n) | O(n) | O(w) 큐 |

전체 저장 공간은 O(n).

## 5. 최악의 경우와 균형 트리로 가는 동기

BST 의 모양은 **삽입 순서**에 달려 있다. 1, 2, 3, 4, 5 처럼 이미 정렬된 값을 차례로 넣으면:

```
1
 \
  2
   \
    3          높이 = n, 사실상 연결 리스트
     \         탐색/삽입/삭제 모두 O(n)
      4
       \
        5
```

정렬된(또는 거의 정렬된) 데이터는 현실에서 흔하다(자동 증가 ID, 타임스탬프 등). 그래서 삽입/삭제 때마다 **회전(rotation)** 으로 높이를 `O(log n)` 으로 보장하는 **자가 균형 이진 탐색 트리**가 쓰인다.

- **AVL 트리**: 두 서브트리의 높이 차가 1 이하가 되도록 엄격히 유지. 탐색이 가장 빠름.
- **Red-Black 트리**: 색 규칙으로 느슨하게 균형을 유지. 삽입/삭제 회전이 적어 라이브러리 표준(`TreeMap` 등)에 많이 쓰임.

이 구현은 BST 의 기본 원리(불변식, 삭제 3가지 경우)를 학습하는 것이 목적이며 균형은 맞추지 않는다.

## 6. TypeScript 로 구현할 때의 장단점·주의점

장점
- 제네릭 `BinarySearchTree<T>` 와 `Comparator<T>` 로 숫자·문자열·객체를 같은 코드로 다룰 수 있다.
- 제너레이터로 순회를 지연 평가하고 `for...of`, 전개 연산자와 자연스럽게 연동한다.
- `TreeNode<T> | null` 타입과 `strict` 모드가 null 처리 누락을 컴파일 시점에 잡아준다.

단점/주의점
- **재귀 깊이**: JS 엔진의 호출 스택은 보통 수천~수만 단계라, 편향된 트리에서 재귀 순회/탐색은 `RangeError` 가 날 수 있다. 이 구현은 모두 반복문과 명시적 스택/큐를 쓴다. (테스트에서 정렬된 2만 개 입력으로 확인)
- **기본 비교자의 한계**: `<`, `>` 는 숫자/문자열에만 의미 있다. 객체는 반드시 comparator 를 주입해야 하고, `NaN` 이나 일관되지 않은 비교자는 불변식을 깨뜨린다. 문자열 기본 비교는 로캘이 아닌 UTF-16 코드 단위 순서다.
- **같은 키 = comparator 가 0**: 중복은 `===` 가 아니라 `compare === 0` 으로 판정한다. 값이 달라도 키가 같으면 무시된다.
- **삭제 시 값 복사**: 경우 3 에서 노드 객체가 아니라 값을 복사한다. 외부에서 노드 참조를 들고 있는 설계라면 노드 자체를 교체해야 한다(이 구현은 노드를 외부에 노출하지 않는다).
- **제너레이터 순회 중 수정 금지**: 순회하는 동안 insert/remove 하면 결과가 정의되지 않는다.
- **성능**: 노드마다 객체 할당이라 배열 기반 정렬 구조보다 메모리와 캐시 효율이 낮다. 균형이 필요하면 AVL/Red-Black 으로 확장한다.
