# 연결 리스트 (Linked List)

`SinglyLinkedList<T>`(단일 연결, head + tail)와 `DoublyLinkedList<T>`(이중 연결)를 구현합니다.

## 1. 추상 자료형(ADT) 정의

순서가 있는 원소의 나열(시퀀스)입니다. 인덱스는 0부터 시작하며, `n`은 현재 원소 개수입니다.

| 연산 | 사전 조건 | 사후 조건 |
|---|---|---|
| `pushFront(x)` | 없음 | `x`가 0번째, 기존 원소는 한 칸씩 뒤로. size = n+1 |
| `pushBack(x)` | 없음 | `x`가 마지막. size = n+1 |
| `popFront()` | 없음 (빈 리스트면 `undefined` 반환, 상태 불변) | 0번째 원소를 반환하고 제거. size = n-1 |
| `popBack()` | 없음 (빈 리스트면 `undefined` 반환) | 마지막 원소를 반환하고 제거. size = n-1 |
| `insertAt(i, x)` | 0 ≤ i ≤ n (정수). 위반 시 `RangeError` | `x`가 i번째가 되고 i 이후 원소는 한 칸씩 뒤로. size = n+1 |
| `removeAt(i)` | 0 ≤ i < n. 위반 시 `RangeError` | i번째 원소를 반환하고 제거. size = n-1 |
| `get(i)` | 0 ≤ i < n. 위반 시 `RangeError` | 상태 불변, i번째 값 반환 |
| `indexOf(x)` | 없음 | 처음으로 `===` 인 원소의 인덱스, 없으면 -1. 상태 불변 |
| `reverse()` | 없음 | 원소 순서가 뒤집힘. size 불변 |
| `size` / `isEmpty()` | 없음 | 개수 / (size === 0) |
| `clear()` | 없음 | size = 0 |
| `toArray()` / `[Symbol.iterator]` | 없음 | 앞에서 뒤로 순서대로 값을 내줌. 상태 불변 |

불변식: `size`는 항상 실제 노드 수와 같고, 비어 있을 때만 `head`와 `tail`이 모두 `null`입니다.
실패한 연산(RangeError)은 리스트를 바꾸지 않습니다.

## 2. 왜 쓰는가

- **앞/뒤 삽입·삭제가 원소 이동 없이 O(1)**: 배열의 `unshift`/`shift`는 모든 원소를 밀어야 하지만(O(n)), 연결 리스트는 포인터만 바꿉니다.
- **이미 위치를 알고 있는 노드의 삽입/삭제가 O(1)**: 이중 연결 리스트에서 노드를 쥐고 있다면 탐색 없이 끼워 넣고 뺄 수 있습니다.
- 실제 사용 예
  - 큐/덱(Deque)의 내부 구현 (BFS, 작업 큐)
  - LRU 캐시: 해시맵 + 이중 연결 리스트로 "최근 사용 순서"를 O(1)에 갱신
  - 텍스트 에디터의 undo/redo 이력, 브라우저의 앞으로/뒤로 가기
  - 해시 테이블의 체이닝(충돌 시 노드 연결), 운영체제의 프로세스/프리 블록 리스트

### 배열과의 비교

| | 배열 | 연결 리스트 |
|---|---|---|
| 임의 접근 `a[i]` | **O(1)** (주소 = 시작 + i×크기) | O(n) (처음부터 따라가야 함) |
| 앞쪽 삽입/삭제 | O(n) (원소 이동) | **O(1)** |
| 중간 삽입/삭제 | O(n) (이동) | 위치를 찾는 데 O(n), 연결 변경은 O(1) |
| 메모리 | 값만 연속 저장 | 노드마다 포인터 1~2개 + 객체 헤더 오버헤드 |

핵심: 연결 리스트의 "중간 삽입 O(1)"은 **이미 그 노드를 가리키고 있을 때**만 성립합니다. 인덱스로 접근하면 탐색 비용 O(n)이 지배적이라, 이 구현의 `insertAt`/`removeAt`도 O(n)입니다.

### 캐시 지역성

배열은 원소가 메모리에 연속으로 놓여 있어, 한 원소를 읽을 때 CPU 캐시 라인에 이웃 원소가 함께 올라옵니다(공간 지역성). 연결 리스트의 노드는 힙 여기저기에 흩어져 있어, 다음 노드로 갈 때마다 캐시 미스가 날 가능성이 높습니다. 그래서 점근 복잡도가 같은 O(n) 순회라도 실제로는 배열이 몇 배 빠른 경우가 흔합니다. "연결 리스트가 이론상 유리하다"가 실측에서 뒤집히는 대표적인 이유입니다.

## 3. 구현 방식

### 단일 연결 리스트 (head + tail)

```
head                                   tail
 │                                      │
 ▼                                      ▼
┌────┬───┐   ┌────┬───┐   ┌────┬───┐   ┌────┬──────┐
│ 10 │ ●─┼──▶│ 20 │ ●─┼──▶│ 30 │ ●─┼──▶│ 40 │ null │
└────┴───┘   └────┴───┘   └────┴───┘   └────┴──────┘
 value next
```

`tail`을 따로 들고 있어 `pushBack`이 O(1)입니다. 하지만 `popBack`은 "tail 바로 앞 노드"의 `next`를 `null`로 만들어야 하는데, 앞 노드를 거꾸로 알 길이 없어 head부터 따라가야 합니다(O(n)).

중간 삽입 (`insertAt(2, 25)`): 앞 노드(20)를 찾고 포인터 두 개를 바꿉니다.

```
before:  20 ──▶ 30
after:   20 ──▶ 25 ──▶ 30      (1) 25.next = 20.next   (2) 20.next = 25
```

`reverse()`: 순회하며 각 노드의 `next`를 이전 노드로 돌립니다.

```
prev=null  cur=10          10 ◀── 20   30 ──▶ 40
                      (10.next = null, 20.next = 10, ... 반복)
최종:  null ◀── 10 ◀── 20 ◀── 30 ◀── 40   → 새 head = 40, 새 tail = 10
```

### 이중 연결 리스트

```
        head                                     tail
         │                                        │
         ▼                                        ▼
null ◀─ ┌────┐ ◀──── ┌────┐ ◀──── ┌────┐ ◀──── ┌────┐
        │ 10 │       │ 20 │       │ 30 │       │ 40 │ ─▶ null
        └────┘ ────▶ └────┘ ────▶ └────┘ ────▶ └────┘
              prev/next 가 서로를 가리킨다
```

노드가 `prev`도 가지므로 `popBack`이 O(1)입니다. 구현의 `unlink(node)`는 앞뒤 노드를 서로 이어 주는 것만으로 어떤 노드든 O(1)에 떼어냅니다. `nodeAt(i)`는 `i < size/2`이면 head에서, 아니면 tail에서 출발해 최대 n/2걸음만 걷습니다.

## 4. 시간·공간 복잡도

| 연산 | 단일 연결 (head+tail) | 이중 연결 |
|---|---|---|
| `pushFront` | O(1) | O(1) |
| `pushBack` | O(1) | O(1) |
| `popFront` | O(1) | O(1) |
| **`popBack`** | **O(n)** | **O(1)** |
| `insertAt(i)` | O(n) (맨 앞/뒤는 O(1)) | O(n) (실제론 최대 n/2 탐색) |
| `removeAt(i)` | O(n) (맨 앞은 O(1)) | O(n) (맨 앞/뒤는 O(1)) |
| `get(i)` | O(n) | O(n) |
| `indexOf` | O(n) | O(n) |
| `reverse` | O(n) | O(n) |
| `size`, `isEmpty` | O(1) | O(1) |
| `clear` | O(1) (GC가 노드 수거) | O(1) |
| `toArray` / 순회 | O(n) | O(n) |

- 공간: 리스트 전체 O(n). 노드당 포인터가 단일은 1개, 이중은 2개라 이중이 더 큽니다. `reverse`는 제자리라 추가 공간 O(1), `toArray`는 O(n).
- **popBack 차이 요약**: 단일은 tail의 이전 노드를 찾으려 O(n), 이중은 `tail.prev`로 O(1). 단일 연결에서 "뒤에서 제거"가 잦다면 이중 연결을 쓰거나 구조를 바꿔야 합니다.

## 5. TypeScript로 구현할 때의 장단점·주의점

- **제네릭 `<T>`** 로 값 타입을 보존하고, 노드는 `SNode<T> | null`로 표현해 strict 모드의 null 검사가 포인터 실수를 잡아 줍니다. 대신 "범위를 검증했으니 null이 아님"을 알려 주려고 `!`(non-null assertion)을 쓰는 곳이 있어, 불변식이 깨지면 컴파일러가 도와주지 못합니다.
- **메모리 해제는 GC 몫**: C/C++과 달리 `free`가 없고, `clear()`는 head/tail만 끊으면 나머지 노드는 GC가 수거합니다. 다만 이중 연결은 순환 참조(서로 가리킴)지만 도달 불가능하면 GC가 회수하므로 문제없습니다. `unlink`에서 떼어낸 노드의 포인터를 `null`로 끊는 것은 안전을 위한 습관입니다.
- **성능 현실**: JS 엔진에서 노드는 개별 객체라 배열(특히 숫자 배열)보다 메모리와 캐시 효율이 크게 떨어집니다. 실무에서 단순 큐가 필요하면 `Array`(또는 링 버퍼)가 더 빠른 경우가 많습니다. 학습/특수 목적(LRU 등)에서 의미가 큽니다.
- **재귀 대신 반복문**: 10만 개 이상에서 재귀로 순회하면 호출 스택이 넘칠 수 있어 모든 연산을 반복문으로 작성했습니다.
- **`indexOf`는 `===` 비교**: 객체는 참조가 같아야 찾아집니다. 값 동등 비교가 필요하면 비교 함수를 받도록 확장해야 합니다.
- **`undefined` 값 저장 주의**: `popFront()`가 빈 리스트일 때 `undefined`를 돌려주므로, `T`에 `undefined`를 넣으면 "빈 리스트"와 구분이 안 됩니다. 구분이 필요하면 `isEmpty()`를 먼저 확인하세요.
- **이터레이터 중 변경 금지**: 순회 도중 리스트를 수정하면 결과가 정의되지 않습니다(배열과 마찬가지로 별도 보호 장치 없음).
